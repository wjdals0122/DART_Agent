구현: [src/api/server.py](../src/api/server.py) · uvicorn 위의 **순수 ASGI**

## 1. `GET /answer`

### 요청

| 파라미터 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `question_id` | string | 권장 | 문항 식별자. 응답에 그대로 되돌려준다 |
| `question` | string | 필수 | 질문 원문. **한글은 URL 인코딩(UTF-8)** |

```bash
curl -s -G "http://49.50.141.125/answer" \
  --data-urlencode "question_id=Q-001" \
  --data-urlencode "question=SK하이닉스 2024년 연결 매출액이 얼마야?"
```

### 응답 — 200 · JSON 5필드 · **전부 문자열**

| 필드 | 타입 | 설명 |
|---|---|---|
| `question_id` | string | 요청에서 받은 값 그대로. 없으면 `""` |
| `question` | string | 요청에서 받은 질문 원문 그대로 |
| `retrieved_context` | string | 답변 근거로 사용한 공시 원문 조각. 문서 단위 블록으로, 각 블록 머리에 회사·보고서·회계연도·기수·접수일·접수번호와 섹션 경로가 붙는다. 근거가 없으면 `"검색된 문서 없음"` |
| `think_trace` | string | 번호가 붙은 추론 경로. 질문 재작성 결과 → 도구 호출과 인자·결과 요약 → 근거 확인 → 답변 작성 → 비고(LLM 호출 수·소요) |
| `answer` | string | 최종 답변. 끝에 `근거` 절로 인용 문서를 붙인다. 근거를 못 찾으면 `"공시에서 확인되지 않음"` |

응답 필드에 `null`은 없다. `make_answer()` 가 반환 직전에 5필드를 모두
문자열로 강제한다([server.py:315-317](../src/api/server.py#L315-L317)).

### 길이

`retrieved_context` 는 **40,000자 상한**으로 자른다(`CONTEXT_CAP`).
자를 때는 문서 단위로 끊고, 답변이 인용한 문서를 먼저 남긴다.
주최측 공지에 "각 필드의 길이 제한은 없다"고 되어 있으나 전송 안정성을 위해 둔 값이다.
나머지 필드에는 상한이 없다.

## 2. `GET /health`

사전 점검에서 접속 확인용으로 쓰는 경로다. 파라미터 없음.

| 상태 | HTTP | 본문 |
|---|---|---|
| 준비 완료 | **200** | `{"status":"ok","warm_seconds":8.7,"served":11,"uptime":116737.9}` |
| 기동 중 | **503** | `{"status":"starting","elapsed":12.4}` |
| 기동 실패 | **503** | `{"status":"error","detail":"<사유>"}` |

- `warm_seconds` — 인덱스·임베딩 모델 로딩에 걸린 시간(초)
- `served` — 기동 이후 처리한 `/answer` 요청 수
- `uptime` — 기동 이후 경과 시간(초)

`/healthz` · `/health/` 도 같은 응답을 준다.

## 3. 그 밖의 경로

| 경로 | HTTP | 본문 |
|---|---|---|
| `GET /` | 200 | `{"service":"공시 Agent 평가 API","endpoints":["/answer?question_id=&question=","/health"]}` |
| 그 외 | 404 | `{"status":"not_found","path":"<요청 경로>"}` |

> `GET /` 의 응답은 **어느 껍데기가 떠 있는지 구분하는 데 쓴다.**
> 위 JSON이면 순수 ASGI(정상), `{"detail":"Not Found"}` 면 FastAPI 경로다.

## 4. 오류 시 동작 — 준비된 뒤에는 언제나 200 + 5필드

5xx를 뱉으면 주최측 재시도 2회를 낭비하고 결국 미응답 처리된다.
그래서 **기동이 끝난 뒤에는 어떤 입력에도 200과 5필드를 돌려준다.**

| 상황 | HTTP | 동작 |
|---|---|---|
| 기동 중 (`/answer`) | **503** | `{"status":"starting","detail":"모델 로딩 중","elapsed":..}`. 주최측 재시도 2회 사이에 준비가 끝나면 정상 서비스된다 |
| `question` 이 비었거나 공백 | 200 | `answer`="질문이 전달되지 않았습니다…" · `retrieved_context`="검색된 문서 없음" · LLM을 부르지 않는다 |
| 에이전트 내부 예외 | 200 | `answer`="공시에서 확인되지 않음" · `think_trace`="1. 처리 중 오류가 발생했다 — {예외타입}: {메시지}" |
| 하드 데드라인 240초 초과 | 200 | `answer`="공시에서 확인되지 않음" · `think_trace`="1. 내부 하드 데드라인 240초를 넘겨 답변 생성을 중단하고 폴백을 보냈다" |
| 라우팅 자체의 예외 | 200 | 5필드 폴백. `think_trace`="1. 라우팅 오류 — …" |
| 근거를 못 찾음 | 200 | `answer`="공시에서 확인되지 않음" (정상 응답이다. 오류가 아니다) |

도구 함수는 어떤 입력에도 예외를 던지지 않고 `{"status": ...}` JSON을 반환한다
(`src/tools/`). 평가 중 예외가 나면 그 문항이 0점이기 때문이다.

## 5. 응답 시간

주최측 타임아웃(문항당 300초, 2026-09-04 공지) 안쪽에 3층으로 여유를 뒀다.

```
주최측 300초  >  API 하드 240초(server.HARD_DEADLINE)  >  에이전트 소프트 200초(loop.DEADLINE)
                                                          ↳ 검문 여유 20초(AUDIT_MARGIN)
```

- **소프트 200초** — 넘어가면 loop가 도구를 더 부르지 않고 마지막 답변을 받아낸다.
  정상 경로의 끝이다.
- **하드 240초** — 답변 생성을 워커 스레드에서 돌리고 `join(240)` 한다.
  스레드가 그때까지 안 끝나면 본 스레드가 폴백 5필드를 먼저 보낸다.
  네트워크 행(hang) 같은 비정상 정지에 대비한 장치다.
- 타임아웃에 딱 맞추지 않는 이유 — 답변을 만드는 도중에 상대가 먼저 끊는다.

### 실측

| 항목 | 값 | 출처 |
|---|---|---|
| 이 문서의 예시 요청 | **8.9초** · 12,511 bytes | 2026-09-06 09:44 실호출 |
| 회귀 7문항 | 11.1 ~ 31.1초 (합 106.3초) | `reports/regression_last.md` (2026-09-06) |
| e2e 40문항 | 60초 초과 3건 · **200초 초과 0건** | `reports/e2e_v6_auto.md` |
| `/health` | 4ms | HANDOFF §9 |
| 기동(모델·인덱스 로딩) | 8.7초 ~ 34.5초 | 현재 서버 `/health`, HANDOFF §9 |

기동 시간은 답변 시간에 포함되지 않는다 — `warmup()` 이 요청을 받기 전에 끝낸다.

## 6. 한글 인코딩

**`scope["query_string"]` 을 bytes 단계에서 직접 percent-decoding 한 뒤
UTF-8 → cp949 순으로 읽는다**(`_params()`).

FastAPI/Starlette은 쿼리를 UTF-8 고정 + `errors=replace` 로 읽는다.
Windows 셸의 curl이 한글을 cp949로 보내는 경우가 있어(실측: `하이` → `%c7%cf%c0%cc`)
그 경로에서 질문이 통째로 U+FFFD가 된 사고가 실제로 있었다.
지금은 **항상 순수 ASGI로 뜬다.** `DART_API_FASTAPI=1` 을 명시할 때만 FastAPI
껍데기를 쓰고, 그 경우에도 쿼리는 같은 `_params()` 로 읽는다.

받은 질문은 `logs/requests.jsonl` 에 UTF-8로 한 줄씩 남는다
(uvicorn access 로그에는 percent-encoding된 경로만 남는다).
인코딩을 LLM 없이 확인하려면 `question` 을 비우고 `question_id` 로만 왕복시킨다 —
`question` 이 비면 LLM을 부르지 않는다.

```bash
curl -s -G "http://49.50.141.125/answer" --data-urlencode "question_id=한글확인"
```

## 8. 운영 메모

- 평가는 **순차 호출**(동시 요청 없음)을 전제로 한다. 인덱스·모델은 프로세스에
  한 벌만 올린다(`get_searcher()` 싱글턴).
- 5xx 응답에 주최측이 **재시도 2회**를 한다. 기동 중 503은 그 재시도로 흡수된다.
- 요청 로그 `logs/requests.jsonl`, 서버 로그 `logs/api.log`.
- 재기동은 `systemctl restart dis044`. `serve.sh` 를 직접 부르면 80 포트가 충돌한다.
